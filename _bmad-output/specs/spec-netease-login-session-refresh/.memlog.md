goal: 让服务能够识别真实登录状态、正确使用最新 Cookie，并在可刷新时安全续期、不可刷新时明确提示重新登录

- (direction by user) 本次工作聚焦 MUSIC_U 登录后获取歌曲 URL、刷新登录 token、掉登录后重新使用新 MUSIC_U 仍无法刷新这条故障链。
- (decision) 服务必须区分 MUSIC_U 原始凭证、持久化完整 Cookie、网易云 token refresh 响应和最终账号可用性，不能把刷新接口返回 HTTP 200 当作登录仍有效。
- (capability) CAP-1：服务能以用户明确提供的最新完整 Cookie 为当前会话来源，避免旧持久化 Cookie 静默覆盖 .env 中的新 MUSIC_U；成功标准是诊断输出能展示来源和脱敏指纹，且请求使用该来源中的 MUSIC_U 与 __csrf。
- (capability) CAP-2：服务能验证登录态和刷新结果的业务有效性；成功标准是同时检查 HTTP 状态、响应 code、账号信息和关键 Set-Cookie，而不是只检查 response.ok。
- (capability) CAP-3：服务能在登录态可刷新时原子保存服务端返回的完整 Cookie，并在并发刷新时合并为一次请求；成功标准是后续播放和账号检查使用最新 Cookie，刷新失败不会覆盖最后一个已知可用会话。
- (capability) CAP-4：服务能识别不可通过 token refresh 恢复的会话并给出重新登录路径；成功标准是刷新被拒绝、账号校验失败或登录类型不支持时返回稳定的状态分类和下一步动作。
- (capability) CAP-5：服务能记录不含凭证的登录会话诊断信息；成功标准是可以判断当前使用的 Cookie 来源、字段完整性、最后更新时间、刷新响应分类和账号校验结果，同时日志不包含 MUSIC_U、Cookie 原文或音频鉴权 URL。
- (constraint) 网易云 Cookie 是敏感凭证，文档、日志、接口响应和提交中只能使用存在性、长度和不可逆短指纹，不能记录原值。
- (constraint) 现有调用链使用 eapi/login/token/refresh；任何协议或请求头更新必须保留对现有播放链路的兼容，并通过真实账号或可复现的脱敏响应验证。
- (constraint) 持久化会话必须避免半写入和并发覆盖；刷新失败时必须保留最后一个已知会话，不能因失败响应清空有效凭证。
- (constraint) 不得假定单独替换 MUSIC_U 就等于完整登录会话；__csrf、NMTID、MUSIC_R_U/MUSIC_R_T/MUSIC_SNS、设备指纹和登录方式的影响必须通过验证决定。
- (constraint) 本项目没有真实线上响应样本和登录方式记录；无法确认的上游拒绝原因必须保留为开放问题，不得在规格中虚构协议更新。
- (assumption) 假设当前服务运行时优先读取 data/account/netease/cookie.json 或 /mnt/account/netease/cookie.json，而不是每次优先采用 .env；本机检查到 data 文件中的 MUSIC_U 指纹与 .env 不同。
- (assumption) 假设用户希望继续使用共享服务端账号和自动刷新，而不是改为每次请求由调用方传完整 Cookie。
- (question) 最新 MUSIC_U 是通过网页版、二维码、手机号/邮箱登录还是客户端抓取得到的？token refresh 对不同登录来源的支持可能不同。
- (question) 刷新失败时网易云返回的 HTTP 状态、业务 code、msg、Set-Cookie 和响应头是什么？需要脱敏后样本才能判断是凭证失效、请求指纹、IP 风控、CSRF 缺失还是接口策略变化。
- (question) 是否允许服务提供一次显式的 replace-session 操作，将 .env 或管理接口提供的完整 Cookie 原子导入持久化存储？
- (note) 当前源码事实：CookieManager.refreshCookie 优先使用本地 Cookie 的 MUSIC_U，只有本地字段为空才回退 env.MUSIC_U；refreshCookie 只保存 headers.get(set-cookie)，不合并旧 Cookie，也不验证写盘是否成功。
- (note) 当前源码事实：GetMusicPlayUrl 调用 CookieManager.getCookie 时未传 IP；getCookie 仅在 cookie.json 不存在时触发刷新，已存在但过期或错误的文件会继续被使用。
- (note) 当前源码事实：本机 data/account/netease/cookie.json 存在，包含 MUSIC_U、__csrf、NMTID、MUSIC_R_U、MUSIC_R_T、MUSIC_SNS、MUSIC_A_T 等字段；其中 MUSIC_U 与 .env 值不同。
- (note) 参考项目 api-enhanced v4.41.1 仍使用 /api/login/token/refresh，统一请求层保留完整 Cookie 对象、补设备字段和 NMTID，并将服务端 Set-Cookie 返回给调用者；未发现仅替换 MUSIC_U 的新刷新机制。
- (note) 外部资料提示：二维码登录 Cookie 通常不支持 login/token/refresh；该结论需要结合当前登录来源和实际响应验证。
